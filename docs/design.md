# パリおすすめデータベース — 設計書

作成日: 2026-08-29
サイト名・IA変更: 2026-08-31(「パリ製パンコンクール図鑑」→「さすけのパリ図鑑」→「パリおすすめデータベース」)

## 目的

パリのパンコンクール情報・むんた(さすけ)のおすすめ店・ミシュラン星付き店をまとめ、日本語圏のパリ旅行者・在住日本人向けに公開する総合データベースサイト。副業として運用する。将来的には常連客への配布や、客自身によるお店の追加投稿も想定する。

## スコープ

- パンコンクール: 大会情報(主催、開催頻度、審査基準、歴代ランキング)、受賞店の地図・訪問ガイド・説明文、現在地/宿泊先住所から近い受賞店を検索する機能
- カテゴリページ(レストラン/ショコラティエ/パン屋さん/お土産/スーパーで買えるおすすめ/ホテル): 各ページに「さすけのおすすめ」(実訪問済み/気になる、の2ステータス)と「先輩カップルのおすすめ」(投稿フォーム経由、承認制)をタブで表示
- ミシュラン星付き: パリの三ツ星・二ツ星レストラン一覧
- 投稿機能: 訪問者が自分のおすすめ店・感想を投稿できる導線(Googleフォーム、詳細は後述)
- 対象言語: 日本語のみ
- 対象コンクール: バゲット部門・クロワッサン部門から開始。将来的に他部門(pain au chocolat等)を追加できる構造にする

## サイト構成(フロントエンド)

- vanilla HTML/CSS/JS。フレームワーク不使用(既存Pholio系プロジェクトと統一)
- **モバイルファースト**: 主要な閲覧はスマートフォンを想定し、レイアウト・タップ領域・文字サイズをまず375px幅で設計してからデスクトップに広げる
- ページ構成:
  - トップページ: 直近の更新・今後の開催予定・各コンクールの最新ランキング(1位のみ)・近くの受賞店を探す
  - コンクール詳細ページ: 年ごとのタブUI。タブを切り替えると、その年の上位5位までと出典リンクを表示(6位以下は出典で確認する形にし、情報量を絞って見やすくする)
  - 近くのパン屋さん検索: 現在地(GPS)または住所/ホテル名を入力し、受賞店を近い順に一覧表示。各結果にも「Googleマップで経路を見る」ボタンを付ける
  - バゲット部門: 2011〜2026年は各年1〜10位を収録(1位はパリ市公式発表、2〜10位はparisbymouth.comの独自集計。当サイトでは出典を明記した上で両方掲載する)。1994〜2010年は情報源(Wikipedia)と他資料の間で受賞者名に食い違いがあり、正確な店舗特定ができなかったため今回は未収録
  - クロワッサン部門: 2018, 2019, 2021〜2026年を収録(2002年開始だが、2020年は開催有無を含め確認できず、2017年以前は店舗が特定できる記録が見つからなかった)
- 日本語化の方針: コンクール名・主催者名・区/県名は日本語表記にする(店名は固有名詞なのでフランス語のまま)。`contests.json`に`name`(日本語)と`official_name`(フランス語正式名称)を両方持たせ、区名はrender.js内の変換テーブルで日本語化する
- 地図の扱い: Google Maps JavaScript APIは使わない(APIキー・課金設定が必要なため)。代わりに `https://www.google.com/maps/search/?api=1&query={店名} {住所}` 形式のリンク(テキスト検索)で、実際の店舗ページ(口コミ・営業時間・写真)が開くようにする
  - 2026-08-31 追記: 当初は `query={lat},{lng}` の座標検索だったが、座標だけだとGoogleがピンを落とすだけで店舗の詳細ページが開かないことがあったため、店名+住所のテキスト検索に変更した(全データファイル対象)。緯度経度自体は「近くの受賞店を探す」の距離計算用に引き続き保持する
- **位置精度**: 全44店舗の座標は、むんたまたはClaudeがGoogleマップで「店名+住所」を実際に検索し、一致した店のURL(`!3d{lat}!4d{lng}`)から取得したもの。自動スクレイピングはGoogle側のボット検出でブロックされるため不可能(claude-in-chrome経由の実ブラウザ操作でのみ可能だった)。それでも住所ベースでは店舗の特定や営業状況までは分からないため、確認時に判明した以下は`shops.json`の`description`に記録し、サイト上に赤字の注記として表示している:
  - 閉業(例: Aux Délices du Palais)
  - 店名変更(例: Boulangerie Mauvieux → 現Boulangerie Gana、Boulangerie Paincé → 正式には Paincé by Elio & Franck)
  - 店舗特定に至らなかったケース(例: Mildo — 該当住所に見つからず)
  - 観光客がアクセスしにくい本店の代わりに支店を掲載したケース(例: Chez Meunier — 本店は19区、掲載しているのはギャラリー・ラファイエット店)
  それでも座標は住所ベースの近似であり得るため、サイトfooterにも「実際の建物位置とずれる場合がある」旨を明記している
- ホスティング: GitHub Pages(無料、既存プロジェクトと同じ運用)

## データ構造

```
data/
  contests.json   # コンクール定義
    { id, name, organizer, category, frequency, official_url, next_edition_date }
  results.json    # 開催年ごとの結果履歴(追記のみ、過去分は残す)
    { contest_id, year, rankings: [{ rank, shop_id, winner_name }], date, source_url }
    # rankings は公式発表された順位分だけを格納する(発表が優勝者のみの年は1件だけになる)
    # shop_id: 店舗が特定できた場合のshops.json参照。特定できない場合は null
    # winner_name: 個人名(受賞者)。店舗不明の年でもこれだけは表示する
  shops.json      # 受賞店マスタ(店舗が特定できたエントリのみ)
    { id, name, address, lat, lng, arrondissement, description, google_maps_url, photo_url }
    # description: 店の紹介文(任意)
    # photo_url: 著作権が確認できた画像のみ設定。無ければ null(Googleマップへのリンクで代替)
```

- 各エントリに `source_url` を必須とし、サイト上にも出典リンクを表示する(未確認情報を断定しないため)
- `shop_id` が `null` の年は、画面上「店舗情報は未確認です」と表示し、Googleマップリンクも出さない(住所不明のまま地図に乗せない)
- 古い年の情報はネット上の一次情報が乏しく、二次資料間で受賞者名の食い違いが見つかることがあった(例: 同一人物の受賞年がサイトによってずれている)。店名・住所は複数資料で裏取りしたものを優先し、個人名は主要参照元の表記をそのまま採用している。完全な正確性は保証できないため、出典リンクを必ず併記する

## 近くのパン屋さん検索

- 位置情報の入力: ブラウザのGeolocation API(現在地の自動取得)と、住所/ホテル名の手入力の両方に対応
- 住所→座標変換(ジオコーディング): OpenStreetMapのNominatim API(無料・APIキー不要)を使用。利用ポリシーに従い、User-Agentを設定しリクエスト頻度を抑える
- 距離計算: 取得した座標とshops.jsonの緯度経度からHaversine公式でクライアントサイドJSにより算出し、近い順にソートして一覧表示
- 店舗写真: 無断使用を避け、`photo_url`が確認済みの場合のみ表示。無い場合はGoogleマップへのリンクで店構えを確認できるようにする

## 自動更新ワークフロー

```
ROLE: パリの製パンコンクール情報の定期巡回・下書き作成担当
GOAL: 新しい開催日程・結果が出ていたら、data/*.json への差分案を用意する
INPUT: contests.json に登録された各 official_url + 補助メディア
TOOLS: WebSearch / WebFetch(読み取りのみ)
TRIGGER: 週1回(頻度は運用開始後に調整可)
OUTPUT: 差分があれば下書きをプロジェクト内の一時ファイルに保存。差分がなければ何も出力しない
APPROVAL: data/*.json への書き込み・git commit/push は、むんたがClaudeとのチャットで内容を確認し承認した後にのみ行う。完全自動公開はしない
FAILURE: サイト構造の変化などで情報を取得できない場合は「確認できず」と記録し、推測で埋めない。次回巡回に持ち越す
LOG: 実行日時・チェックしたURL・検出した差分の有無を記録する
```

運用イメージ: むんたが気の向いた時にClaudeとのセッションを開き「パン大会情報の下書きを確認して」と依頼する。溜まっている差分候補があれば提示し、承認後にデータファイルを更新してコミットする。空振りが続いても長いレポートは作らない。

**実装済み**: Scheduled Task `paris-bread-weekly-check`(毎週月曜9:05)として登録済み。コンクール情報チェックと「今話題のこと」チェックの両方を1つのタスクで実行し、`docs/pending-updates.md` に下書きを追記する(差分がなければファイルに触れない)。data/*.jsonの書き込みやgit操作は行わない。

## 今話題のこと(index.html内、2026-08-31 スコープ拡大・掲載場所変更)

- Instagram/TikTokの公式APIは一般開放されておらず、直接スクレイピングもできない(ボット検出・利用規約の制約)ため、SNSの直接取得は行わない
- 対象はパン屋に限らない。パリでSNS・メディアが話題にしていることなら、レストラン・スイーツ・アクティビティ・イベントなどジャンルを問わず候補にする(むんた確認: 2026-08-31)。目安は3件
- 代わりに、週1回程度Claudeが「Paris viral」「パリ 今話題」等ジャンルを限定しない検索クエリでWeb検索し、ニュース・メディア記事で取り上げられているものを候補として拾い、むんたに提示・承認を得てから `data/trending.json` に追加する(自動更新ワークフローと同じ承認フロー)
- データ構造: `{ id, name, category, arrondissement, address, lat, lng, google_maps_url, description, source_url, added_date }`
- ジャンルを問わなくなったため、パンコンクール専用の`bread.html`ではなくトップページ`index.html`に「今話題のこと」セクションとして掲載する(2026-08-31 むんた指示で bread.html → index.html に移設。`js/index.js`が担当)

## ミシュラン星付き(2026-08-31 追記)

- `data/michelin.json` に、パリのミシュランガイド2026年版の三ツ星9店・二ツ星20店(計29件)を収録
- 一つ星(パリ約100店規模)は収録しない方針(むんた確認: 2026-08-31。「名前と場所だけ並んでも困る」ため、二ツ星以上の厳選リストに留める)
- データ構造: `{ id, name, hotel, stars, arrondissement, address, lat, lng, google_maps_url, description, source_url }`

  - `description`: シェフ名・料理スタイルの一言(mesinfos.fr、paristourism.org、le75restaurant.com、Web検索で個別に補完。2026-08-31 全29件に追記)

- パンコンクール・おすすめとは完全に独立した静的リストであり、自動更新の対象外(ミシュランガイドの改訂時に手動更新)

## アクセス設計(2026-08-31 方針確定)

- カテゴリページ群は他ページと同様に `.site-nav` とトップページの `category-grid` に通常表示する(サイト構造としては何も隠さない)
- アクセス制御はサイト構造(ナビの有無)ではなく配布経路で行う: サイトのURLはむんたが直接渡した相手にしか渡らない前提とし、公式LINEの全体公開(リッチメニュー等)には出さない
- パスワード等の認証も付けない。「信用している相手にしか渡さない・相手も勝手に転載しない」という前提で運用する(2026-08-31 むんた確認)
- 検討したが不採用: 特定ページだけナビから外して隠しURL化する案。むんたの運用はURL自体を直接手渡しするだけなので、サイト内で個別ページを隠す必要はないと判断
- 2026-09-01 追記: GitHubリポジトリは公開(public)で作成した(`SasukechanParis/paris-osusume-guide`)。非公開リポジトリでGitHub Pagesを使うにはGitHub Pro(有料)が必要なため。公開リポジトリだとソースコード自体は誰でも見られる(≒デプロイ先URLも見つけられる)が、掲載内容はレストラン・ホテルの感想程度で機密性がないためむんた了承のうえで公開を選択。公開URL: https://sasukechanparis.github.io/paris-osusume-guide/

## SEO・検索露出対策(2026-09-01 追記)

- 全ページに`<meta name="robots" content="noindex, nofollow">`、リポジトリ直下に`robots.txt`(`Disallow: /`)を追加
- 背景: サイト公開直後にWeb検索(AI検索ツール経由)で本サイトが実際にヒットすることが判明した。「URLは直接手渡しした人にしか渡らない」という前提の運用だったが、検索エンジン・AIクローラーからは既にアクセス可能な状態だったため、露出を減らす対応を行った
- 効果の限界: noindex/robots.txtは行儀の良いクローラーへの「お願い」であり、強制力はない。既にインデックス済みの検索エンジンから消えるまでには時間がかかる場合があり、URLを直接知っているAIが都度取得するようなケースは防げない。あくまで「新規の一般検索で見つかりにくくする」ための対応

### passages.jsonのGoogleマップリンク修正(2026-09-02 追記)

- むんたから「パッサージュのGoogleマップリンク、Galerie Vivienne以外はどれもただの道路にしかならない。史跡としてちゃんとGoogleマップ上にあるはずだから直して」との指摘

- **未検証の注意点**: この環境のブラウザではGoogleマップがJSアプリを正常にレンダリングせず(自動化ブラウザ避けと思われる簡易HTML版が返る)、実際にどのパッサージュがスポットカード表示になるかをこちらで目視確認できていない。むんたに実機での確認をお願いしたい

## 外部監査(2026-09-03)への対応

外部監査会社から`data/michelin.json`のGoogleマップリンク・住所・座標に関する指摘を受け、独立に再検証のうえ修正した。詳細な判定・変更ファイル・根拠・新規発見・未修正項目はセッション報告を参照。要点のみ記録する。

- **原因**: 一つ星98軒をWikipediaの店名だけでNominatimジオコーディングした際、同名の別施設(パリ以外・別国のものを含む)に誤ってマッチしたケースが複数あった(例: 「AT」がウィーン近郊、「Bellefeuille」がノルマンディーの狩猟地に飛んでいた)
- **対応方針**: 監査の指摘をそのまま採用せず、各施設についてWeb検索で公式住所を確認したうえで、店名+確認済み住所でNominatimに再ジオコーディングする方式に切り替えた(店名だけの検索はもう使わない)
- **修正件数**: 監査指摘8件+独自の静的解析で追加発見した4件(Pantagruel・Le Sergent Recruteur・Pilgrim・Pur、いずれも実在するがarrondissementまたは住所が別施設のものだった)+住所欠落だった短命店8件、計20件のフィールドを修正。Anneは監査・自己点検の双方で住所と区の不一致(75004 vs 3区)が疑われたが、Place des Vosgesという区境の建物特有の事情(情報源によって75003/75004の表記が割れる)と判断し、座標・場所自体は変更せず住所の郵便番号表記のみ自区表示(75003)に揃えた
- **再発防止テスト**: `tests/data.test.js`に(1)パリ+近郊の座標範囲チェック、(2)住所の郵便番号とarrondissementフィールドの整合性チェック、(3)3文字以下の短い店名には住所必須、の3種を追加。michelin.json・shops.json両方に適用
- **見送った項目**: passages.jsonの短縮URL全16件は改めてリダイレクト先を確認し、既存の座標と一致することを検証済み(変更なし)。robots.txtの`Disallow: /`はむんた自身が2026-09-01に意図して設定したものと確認済みのため変更せず。award_name/current_name分離(9番)は既存UI・テストへの影響が大きいため今回は未実装(将来検討)
