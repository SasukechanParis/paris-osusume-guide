# パリおすすめデータベース

パリのパンコンクール受賞店、さすけと先輩カップルのおすすめ(レストラン・カフェ・スイーツ(ショコラティエ・パティスリー)・パン屋さん・お土産・スーパーで買えるおすすめ・ホテル)、ミシュラン星付き店をまとめた静的サイト。

## 英語版(`/en/`、2026-09-11〜)

日本語版(このREADME記載の全ページ)とは別物として、`/en/`配下に公開・SEO向けの英語版を追加した。日本語版は非公開(`noindex`・手渡し運用)のまま変更していない。英語版の設計方針・URL構成・アフィリエイト設計・先輩カップル情報を一切使わない方針などは [`docs/en-site-plan.md`](docs/en-site-plan.md) を参照。

## ページ構成(日本語版)

- `index.html` — トップページ(上部に「近くから探す」「目的から探す」「カテゴリから」「困ったとき」の4つの入口、続いて近く検索のカテゴリ選択・「今どうしたい?」・最近追加されました・今話題のこと・カテゴリ一覧。挿絵は操作より後ろ)
- `menu.html` — メニュー(全ページの入口。下部タブの「メニュー」から開く。中身は `js/shell-data.js` から自動生成)
- `emergency.html` — パリで困ったら(緊急時13シナリオ。結論→行動→詳細の順、電話番号はtel:リンク)
- `airport.html` — 空港アクセスガイド(CDG/オルリー/ボーヴェの交通手段別比較。廃止済みサービスは掲載しない方針)
- `shoot-day.html` — 撮影当日ガイド(前撮り予約者向け。前日の準備・持ち物・天候と撮影の一般的な目安は公開済み、さすけ個別の判断・指示は準備中で「近日公開予定」表示)
- `bread.html` — パンコンクール(日程・ランキング・近くの受賞店検索)
- `contest.html` — コンクール詳細(年別タブ)
- `michelin.html` — ミシュラン星付きレストラン一覧(近くの店検索つき)
- `restaurants.html` — レストラン・カフェ(「レストラン」「日本食が恋しくなったら」「カフェ・サロン・ド・テ」の3セクション、「さすけのおすすめ」⇔「先輩カップルのおすすめ」タブ、近くの店検索つき。「日本食が恋しくなったら」は`recommendations.json`の`category: "restaurant"`のうち`group: "japanese"`を付けた6件を表示し、一般のレストラン一覧からは除外する)
- `chocolatiers.html` — カテゴリ別おすすめ(「さすけのおすすめ」⇔「先輩カップルのおすすめ」タブ、近くの店検索つき)
- `hotels.html` — ホテル(「さすけのおすすめ」⇔「先輩カップルのおすすめ」タブ。ホテルの推薦はさすけ自身が主(撮影で500件以上のホテルを訪れており比較ができるため)。先輩カップルは一度しか宿泊できず比較できないため、ホテルの新規投稿は受け付けない方針(投稿フォーム側で停止)で、2026-09-20時点で既に届いていた3件のみ掲載。特別なホテル(Ritz Paris・Airelles Château de Versailles, Le Grand Contrôle)は別枠で紹介。近くの店検索つき)
- `bakeries.html` — パン屋さん(パンの種類・注文フランス語つき) / `souvenirs.html` — お土産(選び方・食品持ち込み注意点つき) / `supermarket.html` — スーパーで買えるおすすめ(食材の見分け方つき)。いずれもカテゴリ別おすすめ一覧+近くの店検索は共通
- `flea-markets.html` — 市場(常設の蚤の市3件+食品マルシェなど79件、不定期フリマの案内、近くの市場検索つき)
- `free-spots.html` — 無料スポット(無料の美術館・広場6件+パッサージュ16件、近くのスポット検索つき。公衆トイレ581件の近く検索も別枠で設置)
- `guide.html` — 旅行ガイド(建築さんぽ・旅行実務FAQ・レストランの使い方・お得な支払い方法・免税Détaxe/PABLO・荷物預かり。出典付きの静的コンテンツ、JSONデータなし)
- `map.html` — 地図(全カテゴリのピンをLeaflet.js + OpenStreetMapで1枚の地図に表示、カテゴリ・区で絞り込み可能、現在地・住所検索つき。公衆トイレは件数が多いため初期状態は非表示)
- `toilets-map.html` — トイレマップ(公衆トイレ581件のみをLeaflet.jsの地図で表示。map.htmlのカテゴリチェックボックスを操作する手間なしに全件見られる専用ページ。区の絞り込み・現在地/住所検索つき)
- `shop.html` — 店舗単位ページ(`?id=`で指定した店の全コンクール受賞歴を年度横断で表示、複数受賞バッジ付き)
- `post.html` — 投稿する(Googleフォームへのボタンリンク)

## ローカルでの確認方法

```bash
python3 -m http.server 8420
```

ブラウザで `http://localhost:8420/` を開く。JSやCSSを直したのに古い表示のままのときは、ブラウザのキャッシュが原因なのでハードリロード(またはキャッシュ無効の開発者ツール)で確認する。

## スマホ優先の共通シェル(2026-09-21〜)

日本語版の全ページは、上部バー(サイト名+常設の「困ったとき」)と下部タブ(ホーム・探す・地図・メニュー)を共通で持つ。**この部分は各HTMLに静的に書き込まれたブロックで、定義は `js/shell-data.js` の1か所だけ**。ナビを変えるときは:

1. `js/shell-data.js`(`TABS` / `MENU_GROUPS` / `PAGE_TAB`)を編集する
2. `node scripts/apply-shell.mjs` を実行する(全ページの `<!-- shell:… -->` ブロックが更新される。`--check` で同期ずれの検査だけできる)
3. `node --test` で全ページが同期していること・ピンチズームを妨げていないこと・「困ったとき」が全ページにあることを確認する

新しいページを足すときは、`<!-- shell:top --><!-- /shell:top -->`(`.tricolore-rail` の直後)を置き、`.page` を閉じる `</div>` の直後に `<script>` が続く形で書いてから上のコマンドを実行する。日本語版専用のスタイルは `css/mobile.css`(`body.jp` 配下)に書く。**`css/tokens.css`・`base.css`・`style.css`・`map.css` と `js/geocode.js`・`js/nearby.js`・`js/distance.js` は英語版(`/en/`)が共有しているため、既存の挙動を変えないこと**。

- ボタン・リンクは44×44CSS px以上、入力欄は16px以上(iOSの自動拡大を防ぐ)、ピンチズームは禁止しない
- データ取得は `js/data.js` の `loadJson`(HTTPエラー・タイムアウト・壊れたJSONを `DataLoadError` にして投げる)を通し、各ページの初期化は `js/page-init.js` の `runPage` / `loadSection` で包む。「データが0件」と「通信に失敗」を別の表示にする(`js/ui-status.js`)
- 外部リンク・メニューから戻ったときのスクロール位置とタブ選択は `js/state-restore.js`(sessionStorage、使えなくても何も壊れない)
- 近く検索(`js/nearby-search.js`)は、現在地(押したときだけ許可を求める)・主要地点(`js/spots.js`、座標はOpenStreetMapで確認)・住所/ホテル名(明示的な実行のみ。複数候補は選択)から。距離は直線距離で、徒歩分数は出さない。経路ボタンはGoogleマップの経路画面(`js/maps-links.js`。出発地点は利用者が選んだ場合だけ渡し、GPSの位置はURLに載せない)
- 店舗カードは写真がなくても成立する形(名前・要点・確認済みの条件・推薦元・操作ボタン)。長い説明は3行で折りたたみ「続きを読む」(`js/card-actions.js`)
- 地図(`map.html`・`toilets-map.html`)は1画面に収まる構成。トイレ581件は「公衆トイレ」にチェックを入れたときだけ取得する。Leaflet(CDN)が読めなくても、一覧から探せる案内を出す

## 探す(`search.html`、2026-09-21〜)

店・施設・記事を同じ検索窓で探し、条件で絞り込み、基準地点(現在地・主要地点・保存したホテル・住所)から近い順に並べ、一覧⇔地図を切り替えられる。下部タブの「探す」の行き先。

- **データ統合(`js/places.js`)**: 既存のJSON(おすすめ・先輩カップル・受賞店・ミシュラン・話題・市場・無料スポット・パッサージュ・トイレ)を読み取り用に共通の形へそろえる。元のJSONの形は変えない。IDはデータセット別の接頭辞付き(`r.septime` / `m.septime` …。`r`=さすけ `g`=先輩 `s`=受賞店 `m`=ミシュラン `t`=話題 `f`/`a`=市場 `e`=無料 `p`=パッサージュ `w`=トイレ)。
- **同一店の統合は `data/place-aliases.json` の対応表だけ**。住所などの根拠を `basis` に書いたものを `same_place` に足す。別支店は `keep_separate` に記録し、まとめない。`node --test` が対応表と実データの整合を検証する。
- **別名辞書 `data/search-aliases.json`**: 「ラーメン=ramen」「免税=détaxe=tax free」など、探し方の言い換えだけを書く(全角半角・大小・アクセント・ひらがな/カタカナは自動で吸収)。
- **記事の索引 `data/search-articles.json`**: 旅行ガイド・空港・緊急・撮影当日・お土産の選び方の見出しとカードから**自動生成**する。**記事(`guide.html` など)を直したら `node scripts/build-article-index.mjs` を実行**する(直し忘れは `node --test` が検出する)。記事のカードに `id` を付けると、その位置へ直接リンクできる。
- **確認済みの条件 `data/place-facts.json`**: 予算・予約・屋内・日曜営業を、確認できた店にだけ足す(キーは uid、`verified_on` と出典)。値がある項目だけが画面と絞り込みに出る。空欄=未確認で、「安い」「予約不要」などとは扱わない。
- **URLで再現できるのは共有してよい条件だけ**(`q`, `cat`, `src`, `st`, `arr`, `jp`, `near=spot:<id>|hotel`, `r`, `view`)。現在地・入力した住所・ホテルの座標は決してURLにも計測にも入れない。「戻る」で条件と一覧/地図を復元する。
- **ホテル周辺の保存**: 住所検索で見つけた場所を、利用者が「宿泊先として保存」を押したときだけ、名前と座標を端末内(`localStorage`)に保存する。変更・解除ができ、保存日を表示する。
- **トイレ581件**は、カテゴリ「トイレ」を選ぶか「トイレ」と検索したときだけ取得する。Leaflet(地図)も「地図」を開いたときに初めて読み込む。

## 保存した場所・共有(`saved.html`、2026-09-21〜)

各カードの「保存」ボタン(`js/save-buttons.js`。全ページ共通)で、行きたい場所を端末内(`localStorage`)に集める。ログインなし。下部タブの「保存」にバッジで件数を出す。

- **保存するのは公開データの uid(`js/places.js`)・並び順・「行った」印・保存日だけ**。名前・ホテル・メモ・位置情報は持たない。保存データは `paris-osusume-guide:v1:saved` キー(形式を変えるときは `js/storage.js` のバージョンを上げる)。上限100件。
- おすすめとミシュランのように同一店が複数のデータにある場合は `data/place-aliases.json` の統合先IDで1件として数える。保存後にデータから消えた店は「現在のデータにない項目」と表示し、リストから外せる。
- `localStorage` が使えない・容量不足・壊れたデータでも例外を出さず、その旨を画面に出す(このセッション中はメモリ上で動く)。
- **共有は「共有した時点のコピー」**(共同編集・自動同期ではない)。リンクは `saved.html#s=v1~r.septime~g.…`(`js/share.js`)で、含まれるのは uid と順序だけ。URLフラグメントなのでサーバーにも計測にも送られない。長いリンクは「テキストをコピー/ファイルに書き出す」を案内する。受け取った側は内容を確認してから追加する(既存リストは置き換えず、重複は追加しない。不正な項目・データにない項目は読み飛ばして件数を表示)。
- Web Share API がなければリンクのコピー、Clipboard API がなければ選択できる欄にフォールバックする。

## 旅の流れ・公式情報・フランス語カード・撮影準備(2026-09-21〜)

- **旅の流れ(`journey.html`、`data/journey.json`)**: 出発前/パリ到着日/撮影前日・当日/自由時間/帰国前・帰国日の5つの入口。中身は**既存の記事・機能へのリンクと、確認するもののチェック項目だけ**(記事は複製しない)。リンク先のページ・アンカーの存在は `node --test` が検証する。チェックは端末内に保存(`js/checklist.js`)。
- **公式情報カード(`data/official-info.json`)**: ETIAS・EESなど入国関連。**書いてよいのは、公式ページ(欧州委員会・EU・在外公館)で確認できたことだけ**。各カードに「何を確認するか/どの旅行者向けか/公式リンク/確認日/出典(各出典の日付つき)」を持つ。開始時期・費用・状況は変わるため、**定期確認の対象**(`data/freshness.json`)。予定日が過ぎても自動で「申請必須」にはしない。申請はこのサイトでは受け付けず、旅券番号なども入力させない。カードを更新したら、`verified_on` と本文中の日付・出典を一緒に直す。
- **フランス語カード(`french.html`、`data/french-cards.json`)**: 日本語の用件 → フランス語 → 「相手に見せる」で全画面表示(閉じる操作・フォーカス復帰つき。向きの固定回転はしない)。コピー・お気に入り(端末内)。読み上げは、フランス語の音声がある端末でだけ出る任意機能で、自動再生しない。`from` が付いた表現は旅行ガイドに載っている既存のもの(読み方のカタカナもガイドのもの)で、それ以外にはカタカナ読みを付けない。医療・アレルギーなど誤りが重大な表現は載せない。
- **撮影準備(`shoot-day.html`)**: 既存の案内を、前日・出発前のチェックリストに整理(案内本文は変えていない)。チェック状態と、集合時間・集合場所のメモは端末内だけに保存し、印刷・PDF保存用のCSSがある。

## 目的から探す・モデルコース・ホテル比較・確認済みの条件(2026-09-21〜)

- **目的から探す(`purpose.html`、`js/purpose-core.js`、`data/purposes.json`)**: 撮影後の食事・座って休憩・日本食・雨の日・お土産の5つ。**生成AIや外部APIは使わず**、既存データの確かな項目だけで少数の候補を選ぶ(選び方はコードにあり、テストで検証)。「合う理由」も、推薦元・未訪問/おすすめ・ミシュランの星・直線距離・説明文の語(雨の日の「屋内」は説明に博物館・美術館・図書館とあるものだけ。テラス・広場・公園は屋内と呼ばない)など、データにある事実だけ。ドレスで入店できる・予約なしで入れる・待ち時間がない、などは言わない(`caveat` に「確認していません」と書く)。撮影を終えた場所などの起点は利用者が選ぶ(現在地は押したときだけ。位置はURLに載せない)。
- **モデルコース(`data/courses.json`、`js/courses.js`)**: 既存の場所ID(uid)を並べるだけで、新しい推薦は作らない。`status: "published"` だけが画面に出て、`draft`(運営者の確認・推薦が必要)は出さず、入口も作らない。所要時間は書かず、区間ごとにGoogleマップの経路画面へつなぐ。公開コースには根拠(`basis`)を書く。
- **ホテル比較(`hotels.html`、`js/compare-core.js`、`js/hotel-compare.js`、`data/hotel-facts.json`)**: 「比較に追加」で最大3件を、項目ごとに縦に並べて比べる。**確認できた項目だけ**を載せ、未確認は「未確認」(あり/なしにしない)、1軒も確認できていない項目は行ごと出さない。さすけ=撮影で訪れた(宿泊ではない)、先輩カップル=実際に宿泊、を区別する。宿泊日で変わる価格・部屋タイプで変わる設備・外来撮影の可否は保証として扱わない。
- **確認済みの条件を足す(`data/place-facts.json`)**: 店ごとの「何がおすすめ(`pick`)/どんな人向け(`for`)/予算(`budget`: 区分`€`〜`€€€`・`meal`・`per`・確認日・根拠)/予約(`reservation`)/屋内(`indoor`)/日曜営業(`sunday_open`)/注意点(`caution`)」と、お土産の「誰向け(`for_whom`)/価格の目安(`price_eur`)/保存条件(`storage`)/かさばり(`bulk`)」。キーは uid(`r.septime` など)。条件を書くときは `verified_on`(確認日)と `source`(根拠)が必須で、`node --test` が検証する。値がある項目だけが、カード・検索の絞り込みに出る。初回から全件を埋めず、利用が多そうな店から少しずつ足す。

## オフライン閲覧(2026-09-21〜)

通信が不安な旅先向け。**利用者が設定ページ(`settings.html`)で「オフライン用に保存」を押したときだけ**、必要なファイルを端末(Cache API)に保存する。保存していない内容は、オフラインで使えるとは約束しない(開こうとすると「オフラインです」の案内を出す)。

- **仕組み**: `sw.js`(Service Worker)は、通信できるときは常に最新を取りに行き、通信できない・遅いときだけ、保存済みの内容を返す(自分では何も保存しない)。保存は `js/offline.js` がページ側で行い、`pack-<VERSION>` に**同じ版のHTML・JS・CSS・JSON一式**を入れる(古いHTMLと新しいJSが混ざらない)。失敗したときは古い保存を消さない。保存日時・版・ファイル数・容量を表示し、いつでも削除できる。サイトが更新されると「保存内容は古い版」と表示し、更新のお知らせも出す(**再読み込みは利用者が押したときだけ**。入力途中で勝手に再読み込みしない)。
- **何が保存されるか**: `data/offline-pack.json`(**自動生成**)。対象ページ(緊急・撮影準備・保存した場所・フランス語・旅の流れ・空港・ガイド・検索・目的・メニュー・設定)から、CSS・JSのimport・画像・データJSONを辿って集める。**ページやJSを直したら `node scripts/build-offline-pack.mjs`** を実行(直し忘れ・保存し漏れは `node --test` が検出)。ファイルの合計は約1MB(2026-09-21時点で98ファイル。設定ページには実際に保存された量が表示される)。トイレ581件(約400KB)は、保存した場所にトイレがあるときだけ。元の大きなPNGは含めずWebPだけ。
- **範囲**: スコープはこのサイトのフォルダ内(GitHub Pagesでは `/paris-osusume-guide/`)。**`/en/` と、同じドメインの別プロジェクトには影響しない**(Service Worker が素通しする)。地図(Leaflet・OpenStreetMapのタイル)・住所検索・Googleマップは外部サービスなのでオンライン専用で、タイルの一括保存はしない。フォントはCDNで、読めなくても代替フォントで本文が読める。
- **`js/data.js` と `sw.js` の `VERSION` は同じ値にする**(`tests/offline.test.js` が検証)。データ・JSを更新したら、両方を書き換える。
- **端末のデータの確認と消去**: 設定ページで、保存した場所・宿泊先・チェックリスト・お気に入り・オフライン保存を、個別にも一括でも消せる(押したときだけ)。

## 画像(WebP、2026-09-21〜)

## 公式情報の確認日・修正報告・計測(2026-09-21〜)

- **確認日の正本 `data/freshness.json`**: 運賃・免税・緊急番号・入国関連(ETIAS/EES)など、公式情報との照合が必要な項目の一覧。各項目は「記事の編集日・掲載日(`data/updates.json`)」とは別に、**公式資料で事実を確かめた日 `verified_on`** と出典 `source` を持つ。**確認していない項目には日付を入れない**(`null` のまま。今日の日付を自動で入れない)。ETIAS/EESの確認日と出典は `data/official-info.json` が正本で、ここでは `ref` で参照するだけ(二重管理しない)。
- **ページへの表示**: `guide.html`・`airport.html`・`emergency.html` の該当カードに `<div class="fresh-note" data-fresh="項目ID …">` を置くと、`js/freshness-badge.js` が「公式で確認(2026年9月21日): …(出典)」と、確認できていない記述の一覧を書き足す。確認から `recheck_after_days`(既定120日)を過ぎると「確認から時間がたっています」と出る。読み込みに失敗しても本文はそのまま読める。
- **点検 `node scripts/check-site.mjs`**: 内部リンク・アンカー(`#…`)・JSONが指すページ・ID重複・座標・日付(未来日・不正)・確認日と出典の整合を調べる(エラーがあれば終了コード1。`node --test` でも同じ検査が走る)。`--freshness` で、未確認・再確認の時期が来た項目の一覧と「次にすること」を表示。`--external [--limit N]` は外部リンクの疎通確認(参考情報。アクセス拒否・タイムアウトは「自動では確認できない」と表示し、「閉店」「リンク切れ」とは断定しない)。英語版の問題は警告にとどめる(今回の対象外)。
- **「情報が違っていた」(各カードの右下)**: 押すと、閉店・営業時間・場所・リンク・その他から選び、補足(300字まで・任意)を書いて、報告文(店名・ID・ページURL・内容・報告日)を**コピー**できる。**このサイトは報告を受け取らず、何も送信しない**(「送信しました」とは表示しない)。運営者への連絡方法にすでにある LINE などへ貼り付けて送ってもらう。報告だけを根拠に店の情報を書き換えることはしない。**連絡先(フォームやLINE)を設定するには**、`data/site-config.json` の `report.contact` を `{"label": "LINE", "url": "https://…"}` にする(https か mailto のみ。実在する連絡先だけを入れる。未設定なら、コピーだけの画面になる)。Googleフォームへの自動入力(事前入力)はしていない(フィールドIDが分からないため作っていない)。
- **計測(GoatCounter)**: 既存のGoatCounterを使い、追加サービスは使わない。数えるのは、検索(`search`/`search-zero`。コードは query・filter・mixed のみ)、経路を開いた(`route`)、保存(`save`)、共有(`share`)、オフライン保存(`offline`)、フランス語カードの表示(`french`)、報告画面の開閉・コピー(`report`)だけ。**検索語・住所・ホテル・現在地・店名・報告の補足・共有データは送らない**。日本語版の全ページの `<head>` に `js/analytics-guard.js` の設定を差し込み、GoatCounterに送るパスから `?`・`#` 以降を除き、同じサイトの前のページ(検索語つきのURLがありうる)はリファラとして送らず、URLのクエリのうち `ref=` の目印(英数字・-・_ の40字まで)だけを残している。計測がブロックされても全機能が動く。人気順位や効果の数値は、計測結果がないのに作っていない。

## データの更新方法(次回更新するときの手順)

1. `data/contests.json` / `data/results.json` / `data/shops.json` / `data/trending.json` / `data/recommendations.json` / `data/guest-recommendations.json` / `data/michelin.json` を編集する
   - お店・情報を追加したときは `data/updates.json` にも1件追記する(トップページ「最近追加されました」に直近5件が表示される。`id`/`date`/`text`/任意の`link`)。サイトの方針や仕組みの変更は書かない
   - 運賃・免税・緊急番号・入国関連の記述を直したら、公式ページを実際に開いたうえで `data/freshness.json`(ETIAS/EESは `data/official-info.json`)の `verified_on` と `source` を更新する。開いていない項目の日付は変えない
2. 変更の種類に応じて、生成物を更新する
   - ナビ・共通部分(`js/shell-data.js` など): `node scripts/apply-shell.mjs`
   - 記事本文(guide・airport・souvenirsなど): `node scripts/build-article-index.mjs`
   - ページやJSの追加・変更: `node scripts/build-offline-pack.mjs`
3. `js/data.js` と `sw.js` の `VERSION` を、同じ新しい値に書き換える
4. `node --test` と `node scripts/check-site.mjs --freshness` を実行する(エラー0件・未確認の項目が何かを確認)
5. ローカルサーバーで、スマホ幅の表示を確認する
6. コミットする(公開はGitHubへのpush。手順は下の「GitHub Pagesでの公開」)

定期ジョブは追加していない。週1回の巡回は既存の Scheduled Task `paris-bread-weekly-check`(下の「自動更新ワークフロー」)のままで、`check-site.mjs --freshness` の結果は、更新のたびに手で確認する。

Googleマップリンクは店名+住所のテキスト検索(`?api=1&query=店名 住所`)で構成する。座標(`lat`/`lng`)は距離計算専用で、マップリンク自体には使わない。

## アクセス解析(GoatCounter)

全ページに [GoatCounter](https://www.goatcounter.com/)(無料・プライバシー配慮型)の計測タグを埋め込み済み。サイトコードは `paris-osusume` を想定。

**むんたに必要な作業(1回だけ)**: https://www.goatcounter.com/signup で サイトコード `paris-osusume` ・自分のメールアドレスで登録し、届いたメールのリンクから本登録を完了する。以降は https://paris-osusume.goatcounter.com/ でダッシュボードを確認できる。

**個別リンクの目印の付け方**: 人に渡すURLの末尾に `?ref=名前` を付けて共有する(例: `https://sasukechanparis.github.io/paris-osusume-guide/?ref=yamada`)。GoatCounterはこの`ref`パラメータを自動でソース(参照元)として認識し、ダッシュボードで「どの目印から来たか」が見られる。目印なし・見覚えのないソースからのアクセスが極端に増えたら、意図しないルートで広まっている可能性がある。目印の値は**英数字・`-`・`_` の40字まで**(日本語の名前などは、計測の前に捨てられる)。

**送っている内容**(2026-09-21〜): ページのパス(`?`・`#` 以降は除く)、ページのタイトル、画面幅、外部サイトからの参照元、`ref=` の目印、上の固定イベントの回数。検索語・住所・ホテル・現在地・共有データは送らない(詳しくは「公式情報の確認日・修正報告・計測」)。`localhost` からのアクセスは、GoatCounterの標準の仕様で数えられない。
